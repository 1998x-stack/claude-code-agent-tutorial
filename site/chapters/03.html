CHAPTER 03 / 28 · CODING AGENT ENGINEERING

从零实现最小 Agent Loop

在安全的整数计算工具上建立 Messages API 的工具调用循环：严格校验参数，正确回传多工具结果，并用离线测试验证消息顺序。

最小 Agent Loop 到底需要什么

语言模型本身不会读你的本地文件，也不会运行 Python。一个最小的客户端工具 Agent 由三部分组成：通过 API 询问模型下一步、由程序验证并执行模型提出的工具调用、把执行结果追加回历史再问模型。

与可能包含沙箱、调度、权限和恢复的成熟产品相比，这里先使用一个没有副作用的整数加法工具，让我们精确检查循环协议。

定义小而可验证的工具契约

工具是模型可以请求的能力，不是模型自由执行程序代码的许可证。注册工具时用 JSON Schema 描述名称、参数和必填规则；实际执行必须由宿主程序完成。

TOOLS = [{
    "name": "add_numbers",
    "description": "Add two bounded integers.",
    "input_schema": {
        "type": "object",
        "properties": {
            "a": {"type": "integer"},
            "b": {"type": "integer"}
        },
        "required": ["a", "b"],
        "additionalProperties": False
    }
}]

本章的 dispatch_tool() 只接受名字为 add_numbers 的调用，确认参数恰好为 a 与 b，两者均是真正的整数、绝对值不超过 10000；其余输入返回 is_error=true。这不仅是防止崩溃，更是在示范系统对模型输出保持不信任。

完整保留 assistant，再返回全部 tool_result

Messages API 可能在一次 assistant 响应里返回文字和多个 tool_use 块。正确做法是先把原始 assistant 内容整体写入历史，依序执行工具，然后用紧随其后的一条 user 消息包含所有对应结果。每个结果通过 tool_use_id 对应具体调用。

# 省略客户端初始化和 TOOL_SCHEMA
response = client.messages.create(
    model=model, max_tokens=1024,
    messages=messages, tools=TOOLS
)
messages.append({
    "role": "assistant",
    "content": [b.model_dump(exclude_none=True) for b in response.content]
})
if response.stop_reason == "tool_use":
    results = []
    for b in response.content:
        if b.type != "tool_use":
            continue
        text, failed = dispatch_tool(b.name, b.input)
        results.append({
            "type": "tool_result",
            "tool_use_id": b.id,
            "content": text,
            "is_error": failed
        })
    messages.append({"role": "user", "content": results})

一个不能忽略的协议不变量

每个工具调用块都需要匹配的工具结果。工具抛错时也应返回错误结果，不能默默忽略该调用，否则后续轮次可能无法重建正确的协议状态。

stop_reason 决定循环的出口

stop_reason == "tool_use" 意味着应处理当前工具调用并继续；end_turn 表示正常完成当前助手回合。对于 max_tokens 等停止原因，不能简单地当作最终答案：输出可能被截断。还要处理异常、工具超时、用户中止及显式最大步数。

本例把超出轮次与非正常停机变成清晰的异常，而非假装任务已完成。生产系统需要进一步实现重试策略、日志、幂等工具调用和人工中止。

复制完整示例并运行单元测试

真实代码保存在 examples/mini_agent.py，包含输入检查、tool_use 多块处理、错误回传、步数预算和自然语言任务入口。源码并不连接 Shell，也不写文件。

# 不调用模型即可验证协议与拒绝逻辑
python3 -m unittest discover -s examples -p 'test_*.py'

# 只有需要调用真实 Messages API 时才安装 SDK
python3 -m pip install anthropic

# 以下变量仅配置在自己的 shell 环境中
export ANTHROPIC_API_KEY="your-secret-key"
export ANTHROPIC_MODEL="your-supported-model-id"
python3 examples/mini_agent.py "Please add 7 and 5 using the tool"

模型 ID 由实际账户与官方文档决定，本教程不硬编码过时别名。运行可能产生 API 费用；单元测试不需要网络、SDK 或真实密钥。

为何不从 unrestricted Bash 开始

旧式示例把模型字符串直接传给 subprocess.run(..., shell=True)，存在命令注入、破坏文件和外联风险。本章改用纯计算工具；以后扩展读写操作时，必须补上工作目录边界、权限确认与隔离环境。

用确定性测试证明协议没有写错

测试使用模拟客户端，在不发起 API 请求的情况下重放一次含两个工具调用的 assistant 响应。它断言第二轮请求的消息角色恰为 user → assistant → user，后者包含两个分别与原始 ID 对应的结果 3 与 7。

另外两个测试确保：工具名称未知、数字越界与布尔值冒充整数会被拒绝；当 stop_reason=max_tokens 或步数耗尽时，Agent 不会伪装成功。这些测试验证的是我们写的 Harness 的确定性性质，而不依赖模型“刚好遵守提示词”。
