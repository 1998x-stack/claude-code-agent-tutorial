CHAPTER 06 / 28 · CODING AGENT ENGINEERING

构建安全的 Read / Write / Edit 工具层

从 Tool Use 请求到工作区内受控执行：实现 BashPreview、Read、Write、Edit 四件套，解释路径、权限、原子写入与失败反馈的工程边界。

先看一个危险的最小实现

工具的 JSON Schema 告诉模型可以请求什么，却不能把任意字符串变成安全命令。最常见的错误是允许模型生成 command，再直接执行 subprocess.run(command, shell=True)。这把外部文本变成操作系统执行权，用户文档或仓库内的恶意内容也可能间接影响命令选择。

安全范围

本章展示的 BashPreview 并不是 Bash：它只用 Python 模拟 pwd、ls 两条只读操作，刻意不提供任意 Shell 执行。若你需要真实 Shell，必须另外设计 OS 级沙箱、最小权限、可审计批准与超时清理。

四种工具与四种副作用等级

教学工具输入操作授权方式
BashPreview严格的 command 枚举预览工作区 / 列目录默认仅只读
Read工作区内相对路径读取有限大小 UTF-8 文件默认只读；阻止敏感路径
Write相对路径 + 内容只创建新文件必须显式 approved=True
Edit相对路径 + 原文 + 新文唯一匹配后替换必须显式 approved=True

示例仅接受明确注册的工具名和恰好匹配的参数集合，未知工具与多余参数统一形成带错误标记的工具结果。工具命名为教学自定义，并非复刻官方内建工具 Schema。

路径检查为什么复杂

不允许绝对路径、..、符号链接与敏感目录，能过滤许多意外越界。仅用字符串 startswith() 不够：例如工作区 /work/repo 与 /work/repo2 有共同前缀。示例先解析真实路径，再检查目标仍位于被允许的根目录内。

仍需明确：Path.resolve() 与替换之间存在竞争条件，进程可能在检查后遭遇目录变化。教学实现不能抵御同机不可信进程并发修改路径；生产中应使用操作系统级隔离及更严格的文件描述符操作。

Write / Edit：保守地修改文件

Write 的业务语义是创建新文件，已有文件不允许覆盖；Edit 只在 old 在当前文件里恰好出现一次时执行替换。若旧文本出现两次，直接报错，因为“猜一个”会造成不可预期的代码修改。

ws = Workspace(Path("scratch-workspace"))
ws.write("note.txt", "version = 1", approved=True)
ws.edit("note.txt", "version = 1", "version = 2", approved=True)
print(ws.read("note.txt"))  # version = 2

# 同一句旧文本出现两次，Edit 必须拒绝
# 未经批准、超出工作区或敏感文件路径同样拒绝

写入时示例在目标目录建立临时文件，写入并刷新后使用 os.replace()，减少中途失败造成的不完整文件；它不是“安全沙箱”，也不保证跨进程并发修改正确性。

工具注册表与错误反馈

每一次客户端 tool_use 都应该得到对应的 tool_result，包含成功内容或结构化失败原因。以下是我们的分发接口：

text, is_error = workspace.dispatch(
    "Read", {"path": "src/app.py"}, approved=False
)
result = {
    "type": "tool_result",
    "tool_use_id": call.id,  # 原样保存 API ID
    "content": text,
    "is_error": is_error,
}

approved 来自宿主用户的决定，不能由模型在 input 中自报批准。执行器不应该把拒绝自动升级为更多权限，而是返回能够解释失败的结果。

来源边界

Anthropic 的客户端工具协议允许应用自己执行工具，失败时回传 is_error=true。但具体工作区实现、路径策略和 Write/Edit 限制是本教程的选择。

离线验证：真正测试拒绝行为

完整源码位于 examples/workspace_tools.py。它仅依赖 Python 标准库。运行：

python3 -m unittest discover -s examples -p 'test_*.py'

单元测试使用临时目录，不触碰真实项目文件。测试覆盖未经批准写入、已存在文件的拒绝、重复文本编辑的拒绝、目录穿越、符号链接、敏感目录、伪造工具名和意外参数；断言错误时文件没有发生改变。

从教学四件套到真实系统需要什么

为了把四个 API 变成实际 Coding Agent 的生产工具，还需要至少处理：每次读写前的细粒度权限、真实的 OS 沙箱、进程与输出上限、目录并发安全、符号链接与设备文件、二进制和大文件策略、回滚与事务、敏感日志脱敏以及人类可理解的变更预览。

练习：为 Edit 添加“变更前后差异预览”，并用模拟批准回调测试：没有批准时文件字节必须完全不变；同时设计检查拒绝 symlink 指向工作区之外文件的测试。
