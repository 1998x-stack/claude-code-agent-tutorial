CHAPTER 08 / 28 · CODING AGENT ENGINEERING

Agent 主循环：状态机、消息队列与可观测事件

用独立的教学 Runtime 解释主循环的消息不变量、退出条件、取消传播与结构化事件；避免把自建 QueryEngine 的伪代码误写成产品源码。

主循环的难点不是 while，而是状态一致性

一个 Agent 看起来就是“请求模型 → 工具执行 → 再请求模型”，但工程上最容易出错的地方是：模型原始响应何时追加到历史、一次返回多个工具请求如何匹配结果、被取消的任务是否仍继续执行，以及不同停止原因能否被当作完成。

本章构造自有的 run_events() 生成器来讨论这些问题。它不是对某个未经公开验证的 QueryEngine.queryLoop 源码的引用。

消息历史的原子性：一个 assistant，多条工具结果

根据 Tool Use 协议，一次 assistant 响应可以包含文本与多个 tool_use。执行层应先把完整 assistant 内容纳入历史；各工具执行后把相应的 tool_result 收集到一条紧随其后的 user 消息中。每个结果保留原始 tool_use_id。

history.append({
    "role": "assistant",
    "content": [block.model_dump(exclude_none=True)
                for block in reply.content]
})
if reply.stop_reason == "tool_use":
    results = [dispatch_and_encode(call)
               for call in reply.content
               if call.type == "tool_use"]
    history.append({"role": "user", "content": results})

如果工具失败，仍应该产生对应错误结果。如果缺少一个 tool_result，下一轮可能无法满足协议约束。这个不变量比队列具体采用 list、deque 还是异步 channel 更重要。

四类终止必须有不同语义

结果条件用户看到的状态
finalend_turn模型完成当前回合（仍需业务验收）
continuetool_use工具执行后进入下一轮
haltmax_tokens 等非正常原因不完整 / 需要恢复或报告
cancel用户取消或轮次预算耗尽停止并给出原因，不伪装为成功

工具本身的超时、参数错误与权限拒绝是另一个维度：可以反馈给模型并重试，但必须有上限，不能无限重试或不断放宽权限。

为什么要把事件和最终结果分开

CLI、IDE 与审计器通常都想看到进展。如果等到全部完成才返回，用户会失去过程可观测性。因此一个教学型生成器可以逐步发出 request、tool_result、final 或 halt 事件，让多个消费者订阅相同状态。

与真正的 Messages Streaming API 要区分：本示例只在一次完整模型响应返回后生成相关事件，没有解析增量 token 或尚未完成的 JSON 输入。若需要 token 级 streaming，应按照官方的事件结构、断点和重试规范另建解码器。

完整可测的事件生成器

源码见 examples/agent_engine.py，无需 SDK 即可用模拟客户端运行。最小用法：

events = list(run_events(
    fake_client,
    model="test-model",
    task="add 2 + 3",
    tool_handler=validated_dispatch,
    max_turns=4,
))
for event in events:
    print(event.kind, event.turn, event.detail)

主循环在进入每次模型请求前检查取消，在每次响应后保存完整内容；为所有工具调用返回结果，转换执行异常为错误结果，并用显式的 halt 描述非正常停止。这样可以通过不依赖模型随机输出的方式测试流程。

故障注入：验证不会假成功

运行 python3 -m unittest discover -s examples -p 'test_*.py'。测试覆盖：一次响应含两个工具、后续 user 消息顺序、工具抛异常仍回传失败、max_tokens 不返回 final、取消任务不发起模型请求。

实现仍需增加什么

该生成器没有网络 Streaming、并发池、超时取消传播、预算账本或持久化恢复。它示范协议状态机和事件接口，而不是生产级 Agent Runtime。

练习：对每条事件加入可审计 ID

练习：给每个请求分配确定性的 run_id 与 turn_id，要求日志在不记录用户密钥、完整敏感工具输入的前提下复原“请求 → 多工具结果 → 终止原因”的时间线。思考如何防止同一个外部任务被自动执行两次。
